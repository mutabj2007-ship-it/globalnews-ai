  - The global-reach acquisition worker uses the same rule.

## D. T2 — Global seven-language foundation (built on H final)

**Branch** `claude/stage2-t2-global-language-foundation` @ **`c3754bdd`** (base `266007c` H final; H's Ask localisation is consumed, not rebuilt). Six commits, 105 files.

### Architecture

- **One `DisplayLocale` authority.** `frontend/src/lib/i18n/displayLocale.ts`, `displayLocale.server.ts`, `documentLocale.server.ts`.
  - Stored values are validated against the seven display locales.
  - A stored choice always wins, which removes the overwrite-to-`pl`.
  - The existing cookie name is kept.
- **Root `<html lang>` / `<html dir>` follow the *effective rendered* locale** (`ar` → `rtl`) through `surfaceLocale.ts` and a generated renderability table.
- **No silent English.**
  - A surface renders the selected locale only if every catalogue namespace it uses is complete.
  - Otherwise it renders consistently in English, with a **declared** fallback notice in the reader's language. The fr–ar notices use the localisation lane's recovered strings.
- **Every route has been moved off the en/pl clamp.** Language controls show the requested locale.
- **`DisplayLocale` is kept separate from the retrieval `LanguageCode`.**
  - Backend: `AnalyzeNewsDto` gains an optional `displayLocale`.
  - The telemetry DTO accepts display locales `de` and `pt`.

## G. T5 — Pre-login consent and guest-trial contract (measured, verified, partly built)

**Part A** — `claude/stage2-t5-consent-guest-trial` @ **`ef0e8b95`** (base `5513275f`).
**Part B** — `claude/stage2-t5b-consent-ui` @ **`72ce054c`** (base T2 `c3754bdd` + Part A).

### Measured guest contract

Identical code at Alpha and Production `5b714833`.

| Aspect | Measured behaviour |
|---|---|
| Quota | **3 completed answers per guest session**, which meets the ≥3 requirement. Reserved before any work. Non-answers don't use a question. |
| Key | Guest cookie `gna_guest`: HttpOnly, SameSite=Lax, Secure, fixed 7-day lifetime. It is minted only on the first guest Send. Per-network daily limits also apply. |
| Claim on sign-in | Moves **all** of that browser's guest conversations, is replay-safe, and clears the cookie. A plain sign-in moves nothing. |
| Retention | Unreadable at 7 days, physically deleted about 24 hours later by the always-on maintenance sweep. That sweep is **not** a defect: it keeps the deletion promise even with Ask V2 off. |
| Enabling the trial | Needs `ASK_IP_UNITS_PER_DAY` ≥ 48000. The code default of 30000 cannot fit 3 answers. |

### Isolation

I1–I9 are proven on a live PostgreSQL 16 database, plus F1–F8 for the delete endpoint: 185 guest tests pass. There is **no leakage** between guests, between a guest and an account, or through a claim.

### Pre-login storage

There is **no analytics, advertising or tracking storage**, so a consent banner or "Accept all" is not needed. Only strictly necessary storage and the language preference are set.

### Built in Part B (non-protected surfaces)

- **Status endpoint.** `GET /ask-v2/guest/status` gains `policy` (allowance, lifetime, grace, sweep interval) and `session.purgeAfter`.
- **Delete endpoint.** `POST /ask-v2/guest/forget` deletes only the caller's own session. It is CSRF-bound, idempotent and never deletes claimed data.
- **UI.**
  - A guest-data section with a delete control on `/privacy` and `/cookies`.
  - A footer link to `/cookies`.
  - Privacy retention wording separating what the always-on sweep guarantees from what needs `RETENTION_SWEEP_ENABLED`.
- **Copy.** 26 consent keys, all marked **PENDING_PO_LEGAL_APPROVAL**. fr–ar render through the T2 declared fallback.
